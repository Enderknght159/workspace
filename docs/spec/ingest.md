# مواصفة تفريغ البطاقة

## المبادئ
1. **لا نكتب على البطاقة ولا نحذف منها.** القراءة فقط.
2. **copy → verify → ثم نقل** داخل المكتب. لا نقل قبل التحقق.
3. كل خطوة قابلة للاستئناف: الدفعة تحمل حالتها وملفاتها في قاعدة البيانات.
4. الهاش `sha256` هوية الأصل، لا الاسم ولا التاريخ.

## الخطوات

```
1. فحص المصدر
   - موجود؟ قابل للقراءة؟ ليس داخل المكتب نفسه؟
   - عدّ الملفات ومسحها (بدون روابط رمزية، بدون SYSTEM VOLUME)
2. معاينة (preview)
   - عدد الملفات، الحجم، الأنواع، التكرارات المعروفة بالحجم+الاسم
   - اقتراح event kind/title/date/slug
   - فحص المساحة: < 60GB تحذير، < 40GB منع
3. نسخ إلى 00_inbox/<batch_id>/
   - robocopy إن وُجد (Windows) وإلا نسخ Node
   - /E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /XJ
   - شريط تقدم كل 250ms عبر SSE
4. تحقق
   - لكل ملف: sha256 + bytes
   - فشل أي ملف = الدفعة failed، لا انتقال
   - تكرار: موجود بنفس الهاش → لا ننسخه مرة أخرى، نربطه بالأصل الجديد
5. تجميع الحدث
   - مجلد الهدف: 10_events/YYYY/MM/YYYYMMDD_<kind>_<slug>/
   - نقل ذرّي (rename) من inbox إلى source/ (أو 20_photos/.../originals)
   - كتابة manifest.json
   - إدخال assets + placements
6. إنهاء
   - batch=completed، event=ingested
   - البطاقة تُترك كما هي، وتُسجَّل بصمة «تم التفريغ» في قاعدة البيانات
```

## التسمية
- slug: `[a-z0-9-]{1,40}` فقط.
- التاريخ `YYYYMMDD` في البداية.
- العنوان العربي في قاعدة البيانات و`manifest.json` فقط.

## الحالات
`previewing → copying → verifying → organizing → completed | failed | cancelled`

## التكرار
- مفتاح التكرار: `sha256`.
- إن وُجد الأصل في نفس الحدث: يُسجَّل `duplicate_of` ولا يُضاف placement جديد.
- إن وُجد في حدث آخر: يُنشأ placement لنفس الأصل (بلا نسخ) ويُنبَّه المستخدم.

## الحدود
- ملف واحد > 64GB: تحذير صريح قبل النسخ.
- مسار > 240 حرفًا: يُستخدم بادئة `\\?\` على Windows.
- أسماء عربية: تُحفظ كما هي داخل الملفات؛ لا تدخل في مسار التخزين.
